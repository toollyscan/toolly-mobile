| D-050 | 2026-08-14 | Accepted | Begin Phase 4 Firebase Authentication implementation, scoped to `dev` only | Real `firebase-auth` SDK dependency, the provider-neutral `AccountAuthenticator` port (shared-core), an Android `FirebaseAccountAuthenticator` adapter, and UI wiring for email/password and pure-phone sign-in have landed, bound exclusively to the `toollyscan-dev` Firebase project (config/dependencies/registry.json, docs/architecture/FIREBASE_ENVIRONMENTS.md). This narrows, rather than removes, D-047/ROADMAP.md's "blocked until Production Gate" framing for Phase 4: dev-environment scaffolding, port and adapter code may proceed now, since PRODUCTION_GATE.md's own merge-review trigger ("processes real user documents... or connects to production cloud infrastructure") is not yet engaged — auth touches no document content, and no build connects to the `production` Firebase project. Connecting any build to `production`, or processing real user documents through it, remains gated on full Production Gate review per its own text. Two real gaps remain open, undecided and explicitly not covered by this decision: (1) canonical `ToollyAccountId` minting is currently a device-local placeholder (no server-side minting authority exists), so it is not yet the cross-device-portable identity ADR-0004 point 3 requires; (2) linking a phone credential to an already-created email/password account (the mandatory post-signup security step) is unimplemented pending the account-linking spike ADR-0004 point 9 already defers. Google/Apple sign-in remain no-ops pending a provider consent-UI adapter. iOS has no `AccountAuthenticator` adapter yet. | shivayogih |
