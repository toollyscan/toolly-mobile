# Product Scope

Toolly: Document Scanner — V1 product scope definition.

---

## Product vision

Toolly is a privacy-first, offline-first document-scanning and management application for Android
and iOS. It enables individuals and small businesses to capture, organise, search and share
documents from their phone or tablet without surrendering ownership of those documents to a cloud
provider.

Users own their documents. Toolly is a tool, not a custodian.

---

## Target users

| Segment | Description |
|---------|-------------|
| Students | Scanning notes, certificates, assignments and identity documents. |
| Small-business owners | Capturing invoices, receipts, contracts and correspondence. |
| Professionals | Managing government forms, identity documents, licences and reports. |
| Home users | Preserving family documents, medical records and financial papers. |

**Initial geography:** India.
**Initial languages:** English, Hindi, Kannada.

---

## Core user problems

1. Paper documents are lost, damaged or inaccessible when needed.
2. Existing scanning apps are slow, produce low-quality output or require a cloud account.
3. Privacy concerns about uploading personal documents to third-party servers.
4. Poor usability on low-cost Android devices with constrained hardware.
5. Lack of Hindi and Kannada language support in competing products.
6. Difficult document organisation and retrieval after scanning.

---

## Product positioning

Toolly is positioned as a **local-first, privacy-respecting** alternative to cloud-dependent
scanning applications. The core value proposition is:

- Documents stay on the device by default.
- Authentication is required before the first scan. After authentication, capture, organisation, export and access to the local library do not require an active network connection or enabled cloud backup.
- Quality output without requiring high-end hardware.
- First-class Hindi and Kannada language support.

## V1 capabilities

### Authentication

- Authentication is required before the first scan; guest scanning is not part of V1.
- Supported methods are phone OTP, email/password, Google, and Apple Sign In on iOS.
- A canonical `ToollyAccountId` is generated by Toolly; Firebase identities are provider credentials only.
- Toolly-owned application databases must not duplicate plaintext phone numbers without an approved purpose.
- Firebase Authentication processes provider identity data according to its configured service contract and privacy terms.
- Phone numbers, OTP values, tokens and provider credentials must never enter application logs or analytics.
- Trusted-device approval and recovery are required capabilities, but protocol and cryptographic details remain evidence pending. See ADR-0004.

### Document capture

- Camera-based document capture on Android and iOS.
- Multi-page scanning within a single document session.
- No commercial scanning SDK. See D-008.

### Batch scanning

- Capture multiple pages per document in a single session.
- Page limit for free users is a hypothesis requiring cost and user validation.
  *Hypothesis H-001: free batch limit of 10 pages; subject to revision.*

### Edge detection and manual crop

- Automatic edge detection to identify document boundaries.
- Manual crop override when automatic detection is insufficient.

### Perspective correction

- Perspective correction applied to captured pages.
- User can review and re-crop before saving.

### Image enhancement

- Standard enhancement: contrast, brightness and de-shadow.
- Colour, greyscale and black-and-white output modes.
- Advanced enhancement is a premium candidate.

### Document organisation

- Folder-based organisation.
- Document renaming.
- Page reordering within a document.
- Page deletion and re-capture.

### Local search

- Full-text search of document titles and folder names.
- OCR-based text search is a premium candidate; see ENTITLEMENTS.md.

### PDF creation

- Export multi-page document as PDF.
- JPEG export per page.

### Export and sharing

- Share PDF or JPEG via Android and iOS share sheet.
- No watermark on standard free exports. See product principle 2.
- Export of locally owned documents must remain available after subscription expiry.

### Local encrypted vault

- All documents stored in an encrypted local vault.
- Vault key management must use platform-protected key material; algorithm, derivation and recovery details remain evidence pending until security review.
- See ADR-0002 for vault architecture.

### Localisation

- English, Hindi and Kannada UI strings at launch.
- Right-to-left (RTL) layout support is a post-V1 goal.

### Accessibility

- Minimum WCAG 2.1 AA target.
- TalkBack support (Android).
- VoiceOver support (iOS).
- Dynamic type support.

### Subscription management

- Free and premium tiers.
- Monthly and annual subscription options.
- Manage and cancel subscription via platform store.
- Offline entitlement cache for offline launch.
- See ENTITLEMENTS.md and SUBSCRIPTION_LIFECYCLE.md.

### Optional encrypted backup

- Cloud backup is opt-in only.
- Backup is end-to-end encrypted before leaving the device.
- Backup is blocked until the operational and legal gates are approved.
- Provider-neutral backup contract; initial implementation targets Firebase Storage.
- See ADR-0003.

## V1 non-goals

The following are explicitly excluded from V1 scope:

1. **No desktop editor.** Toolly is a mobile application.
2. **No web document editor.** Documents are managed on-device.
3. **No team workspace.** Toolly is a personal-productivity application for V1.
4. **No regulated electronic signatures.** No claim to legal enforceability.
5. **No fax service.**
6. **No competitor code or copied assets.** All code and assets are original.
7. **No automatic cloud upload when backup is disabled.** Backup is opt-in.
8. **No guaranteed handwriting recognition.** Accuracy depends on OCR engine evaluation.
9. **No production SDK offering during initial app launch.** SDK offering is a post-launch decision.
10. **No provider-specific domain model.** Firebase, AWS or any provider SDK types must not enter domain entities.
11. **No unlimited free cloud-storage promise.** Cloud storage quotas are a premium capability.
12. **No intrusive advertising.** See product principle 3.
13. **No watermark on normal free exports.** See product principle 2.

## International expansion considerations

International expansion is a post-V1 goal. The following constraints apply:

- Canonical IDs, encryption envelopes and sync contracts must remain locale-neutral.
- No hardcoded INR amounts in domain code.
- Currency and locale formatting are presentation-layer concerns.
- Additional language packs can be added without architectural changes.
- Entitlement and pricing contracts must accommodate regional pricing.
- GDPR compliance is required before expansion to EU markets.

## Offline-first behaviour

The following must work without a network connection:

- Document capture, cropping, enhancement and saving.
- Viewing and browsing all locally stored documents.
- PDF and image export and sharing.
- Document organisation (rename, move, delete).
- Full-text search of document titles.
- All entitlement checks (using cached entitlement state).
- Subscription management UI (cancel/manage links open on reconnect).

The following require network access:

- OTP authentication.
- Cloud backup and restore.
- Subscription purchase.
- Receipt verification (non-blocking; must not prevent local access on failure).

---

## Privacy and security promises

1. Document images, OCR text, filenames and document metadata are never sent to analytics.
2. Toolly-owned application databases do not duplicate plaintext phone numbers without an approved purpose; Firebase Authentication processes provider identity data under its service terms. Phone numbers never enter application logs or analytics.
3. Cloud backup is opt-in, end-to-end encrypted and controlled by the user.
4. Subscription expiry does not remove local documents or block export.
5. Failed billing verification does not delete or corrupt local documents.
6. Encryption keys and recovery phrases are never logged or sent to analytics.
7. See [SECURITY_BASELINE.md](../security/SECURITY_BASELINE.md) for complete security requirements.
